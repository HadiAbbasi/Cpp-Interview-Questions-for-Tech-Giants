## صورت مسئله

در این سؤال از ما خواسته شده است که **بلندترین زیر رشتهٔ پالیندروم (Palindrome) داخل یک رشتهٔ ورودی را در سریع‌ترین زمان ممکن پیدا کنیم.**

اما قبل از اینکه سراغ الگوریتم برویم، باید بدانیم پالیندروم چیست و چگونه می‌توانیم آن را تشخیص دهیم.

### پالیندروم چیست؟

پالیندروم رشته‌ای است که خواندن آن از چپ به راست و از راست به چپ یکسان باشد.

برای مثال، رشته‌های زیر پالیندروم هستند:

```
BACDCAB
ZDDZ
ABBA
AHA

```

اما `ABCD` پالیندروم نیست؛ زیرا معکوس آن `DCBA` است.

### زیررشته چیست؟

زیررشته (Substring) بخشی پیوسته از رشتهٔ اصلی است.

برای مثال، `ANA` یک زیررشته از `BANANA` است؛ اما `BNA` زیررشتهٔ آن نیست، زیرا کاراکترهای آن در رشتهٔ اصلی پیوسته نیستند.
هدف ما پیدا کردن بلندترین بخش پیوسته‌ای است که پالیندروم باشد. اگر چند زیررشتهٔ پالیندروم با طول بیشینه وجود داشته باشند، می‌توانیم هرکدام را برگردانیم.

## چگونه پالیندروم بودن یک رشته را بررسی کنیم؟

آیا برای بررسی پالیندروم بودن یک رشته باید ابتدا نسخه‌ای معکوس از آن بسازیم و سپس نسخهٔ معکوس را با رشتهٔ اصلی مقایسه کنیم؟

خیر! می‌توانیم این کار را بدون ساختن رشتهٔ معکوس انجام دهیم.

کافی است کاراکترهای دو طرف رشته را با یکدیگر مقایسه کنیم:

* کاراکتر اول را با کاراکتر آخر مقایسه می‌کنیم.
* کاراکتر دوم را با کاراکتر یکی‌مانده‌به‌آخر مقایسه می‌کنیم.
* کاراکتر سوم را با کاراکتر دو‌تا‌مانده‌به‌آخر مقایسه می‌کنیم.
* این روند را تا رسیدن به وسط رشته ادامه می‌دهیم.

اگر در هیچ مرحله‌ای اختلافی پیدا نشود، رشته پالیندروم است.

برای مثال:

```
B A C D C A B
|           |

```

ابتدا `B` را با `B` مقایسه می‌کنیم. سپس `A` را با `A` و بعد `C` را با `C` مقایسه می‌کنیم. در نهایت به کاراکتر وسط، یعنی `D` می‌رسیم.

چون تمام مقایسه‌ها موفق بوده‌اند، رشته پالیندروم است.

### پیاده‌سازی در C++

می‌توانیم از تابع `std::equal` استفاده کنیم:

```cpp
#include <algorithm>
#include <string>

bool isPalindrome(const std::string& str)
{
    return std::equal(
        str.begin(),
        str.begin() + str.size() / 2,
        str.rbegin()
    );
}

```

در اینجا `str.begin` به ابتدای رشته اشاره می‌کند و `str.rbegin` پیمایش معکوس رشته را آغاز می‌کند.

از آنجا که فقط لازم است نیمهٔ اول رشته را با نیمهٔ دومِ معکوس‌شده مقایسه کنیم، تعداد مقایسه‌ها تقریباً نصف طول رشته خواهد بود.

همین منطق را می‌توانیم به شکل صریح‌تری نیز پیاده‌سازی کنیم:

```cpp
#include <string>

bool isPalindrome(const std::string& str)
{
    std::size_t left = 0;
    std::size_t right = str.size();

    while (left < right)
    {
        --right;

        if (str[left] != str[right])
            return false;

        ++left;
    }

    return true;
}

```

در این نسخه، `left` به سمت راست و `right` به سمت چپ حرکت می‌کند. هرگاه دو کاراکتر متناظر متفاوت باشند، می‌توانیم بلافاصله نتیجه بگیریم که رشته پالیندروم نیست.

نکتهٔ مهم این است که یک رشتهٔ خالی یا رشته‌ای با یک کاراکتر نیز پالیندروم محسوب می‌شود؛ زیرا هیچ تناقضی میان کاراکترهای دو طرف آن وجود ندارد.
پیچیدگی زمانی این تابع در بدترین حالت \(O(n)\) و پیچیدگی فضایی آن \(O(1)\) است.

این روش برای بررسی یک رشته مناسب است، اما مسئلهٔ اصلی ما کمی متفاوت است.

**ما نمی‌خواهیم فقط بدانیم کل رشته پالیندروم است یا نه؛ می‌خواهیم بلندترین زیررشتهٔ پالیندروم آن را پیدا کنیم.**

## ۳. پالیندروم‌های با طول زوج و فرد

پالیندروم‌ها از نظر طول دو حالت دارند.

### پالیندروم با طول فرد

برای مثال:

```
BACDCAB

```

این رشته ۷ کاراکتر دارد و یک کاراکتر مرکزی، یعنی `D`، در وسط آن قرار گرفته است:

```
B A C D C A B
      ^
    مرکز

```

### پالیندروم با طول زوج

برای مثال:

```
ABBA

```

این رشته ۴ کاراکتر دارد و مرکز آن بین دو کاراکتر `B` قرار می‌گیرد:

```
A B | B A
    ^
   مرکز

```

اگر فقط کاراکترهای رشته را به‌عنوان مرکز بررسی کنیم، پالیندروم‌های فرد را پیدا می‌کنیم؛ اما برای پالیندروم‌های زوج نیز باید مرکزهای بین کاراکترها را در نظر بگیریم.

این تفاوت در طراحی الگوریتم اهمیت زیادی دارد.

الگوریتم Manacher با استفاده از یک تبدیل ساده، هر دو حالت را به یک ساختار مشترک تبدیل می‌کند.

## ۴. تبدیل رشته برای یکسان‌سازی مرکزها

ایدهٔ اصلی این است که بین کاراکترهای رشته یک جداکننده قرار دهیم. همچنین برای یکسان شدن ساختار ابتدا و انتهای رشته، در این دو موقعیت نیز جداکننده می‌گذاریم.

برای مثال، رشتهٔ زیر را در نظر بگیرید:

```
BANANA

```

پس از تبدیل به این شکل درمی‌آید:

```
#B#A#N#A#N#A#

```

اکنون پالیندروم‌های زوج و فرد را بررسی کنیم.

### پالیندروم زوج

رشتهٔ زوج اصلی:

```
ABBA

```

رشتهٔ تبدیل‌شده:

```
#A#B#B#A#

```

مرکز پالیندروم تبدیل‌شده، جداکنندهٔ بین دو `B` است.

### پالیندروم فرد

رشتهٔ فرد اصلی:

```
ABA

```

رشتهٔ تبدیل‌شده:

```
#A#B#A#

```

مرکز پالیندروم تبدیل‌شده، کاراکتر `B` است.

بنابراین، دیگر لازم نیست دو نوع مرکز را جداگانه مدیریت کنیم. هر پالیندروم در رشتهٔ تبدیل‌شده یک مرکز مشخص دارد.

### چرا این تبدیل جواب می‌دهد؟

فرض کنید یک پالیندروم اصلی دارای \(k\) کاراکتر باشد.

در رشتهٔ تبدیل‌شده، علاوه بر این \(k\) کاراکتر، میان کاراکترهای متوالی آن نیز \(k-1\) جداکننده قرار می‌گیرد.

بنابراین، طول بخش متناظر با آن پالیندروم در رشتهٔ تبدیل‌شده برابر است با:

```
k + (k - 1) = 2k - 1

```

عدد \(2k - 1\) همیشه فرد است.

اگر برای یکسان‌سازی ساختار، در ابتدا و انتهای رشته نیز جداکننده قرار دهیم، دو جداکنندهٔ دیگر به این مجموع اضافه می‌شود. در نتیجه طول کل باز هم فرد باقی می‌ماند:

```
(2k - 1) + 2 = 2k + 1 = 2(k + 1) - 1

```

در نتیجه، با این تبدیل دیگر لازم نیست نگران زوج یا فرد بودن طول پالیندروم باشیم و همهٔ مرکزها روی کاراکترها یا جداکننده‌ها به شکلی منظم قرار می‌گیرند.

نکتهٔ پیاده‌سازی: استفاده از `#` در مثال آموزشی مناسب است، اما اگر رشتهٔ ورودی خودش شامل `#` باشد، ممکن است جداکننده با یک کاراکتر واقعی اشتباه گرفته شود.

در پیاده‌سازی نهایی، رشته را به آرایه‌ای از اعداد تبدیل می‌کنیم و مقدار `-1` را به‌عنوان جداکننده در نظر می‌گیریم. از آنجا که مقادیر `unsigned char` بین صفر تا ۲۵۵ هستند، این مقدار با هیچ‌کدام از آن‌ها تداخل ندارد.

## ۵. روش ساده: گسترش از هر مرکز

پس از تبدیل رشته، می‌توانیم هر موقعیت را مرکز احتمالی یک پالیندروم در نظر بگیریم.

برای هر مرکز:

1. یک موقعیت به چپ و یک موقعیت به راست می‌رویم.
2. اگر دو مقدار برابر باشند، شعاع پالیندروم را یک واحد افزایش می‌دهیم.
3. دوباره یک موقعیت به چپ و راست می‌رویم.
4. این روند را تا زمانی ادامه می‌دهیم که یا دو مقدار متفاوت شوند و یا به مرز آرایه (ابتدا یا انتهای آرایه) برسیم.

برای مثال، در رشتهٔ تبدیل‌شدهٔ زیر:

```
#A#B#B#A#

```

مرکز پالیندروم بلندترین بخش، جداکنندهٔ `#` بین دو `B` است.

با گسترش از این مرکز، مقایسه‌های زیر انجام می‌شوند:

```
B == B
# == #
A == A
# == #

```

تمام مقایسه‌ها موفق هستند؛ بنابراین، کل `ABBA` یک پالیندروم است.

### پیاده‌سازی روش ساده

```cpp
#include <string>
#include <vector>

std::vector<int> palindromeRadiiSimple(
    const std::string& str)
{
    std::vector<int> transformed; // keep char codes and their separators (-1)
    transformed.reserve(str.size() * 2 + 1); // reserve required space

    for (unsigned char c : str)
    {
        transformed.push_back(-1);
        transformed.push_back(static_cast<int>(c));
    }

    transformed.push_back(-1); // end separator

    const int n = static_cast<int>(transformed.size());
    std::vector<int> p(n, 0); // keep palindrome radius of each character

    for (int i = 1; i < n - 1; ++i)
    {
        int left = i - 1;
        int right = i + 1;

        while (left >= 0 &&
               right < n &&
               transformed[left] == transformed[right])
        {
            ++p[i];
            --left;
            ++right;
        }
    }

    return p;
}

```

در این پیاده‌سازی، آرایهٔ `p` شعاع پالیندروم هر موقعیت را نگه می‌دارد.

مقدار `p[i]` نشان می‌دهد که از مرکز `i` تا چه تعداد موقعیت می‌توان در هر دو جهت گسترش پیدا کرد و همچنان مقادیر متناظر برابر باشند.

در این نمایش، شعاع پالیندروم در رشتهٔ تبدیل‌شده دقیقاً برابر طول پالیندروم متناظر در رشتهٔ اصلی است. نهایتاً با بررسی آرایهٔ شعاع‌ها، باید ایندکسی که بیشترین شعاع پالیندروم را دارد پیدا کنیم و با حذف کاراکترهای جداکننده، زیررشتهٔ اصلی متناظر با آن را به عنوان نتیجه `return` کنیم!

### مشکل این روش چیست؟

فرض کنید رشته‌ای با طول هزار کاراکتر داشته باشیم.

در حالت بد، ممکن است برای هر مرکز بخش بزرگی از رشته را دوباره بررسی کنیم.

مشکل اینجاست که ممکن است یک بخش از رشته را بارها بررسی کنیم، درحالی‌که اطلاعات لازم برای تشخیص پالیندروم بودن آن بخش را قبلاً به دست آورده‌ایم.

پیچیدگی زمانی این روش در بدترین حالت برابر است با:

\[O(n^2)\]

برای حل سریع‌تر مسئله باید از اطلاعات پالیندروم‌هایی که قبلاً پیدا کرده‌ایم استفاده کنیم.

این دقیقاً همان ایده‌ای است که الگوریتم Manacher به کار می‌گیرد.

## قدرت اصلی الگوریتم Manacher: خاصیت آینه‌ای

یک پالیندروم بزرگ را تصور کنید که مرکز آن در موقعیت `center` قرار دارد و شعاع آن برابر `p[center]` است.

در این مقاله، `right` را مرز راست انحصاری تعریف می‌کنیم؛ یعنی اولین موقعیتی که خارج از محدودهٔ پالیندروم شناخته‌شده قرار دارد.

بنابراین، محدودهٔ پالیندروم برابر است با:

```
[ center - p[center], right )

```

به صورتی که خود `right` بیرون از دامنهٔ پالیندروم قرار دارد!

برای مثال، اگر مرکز پالیندروم ۲۰ و شعاع ۸ باشد، پالیندروم از موقعیت ۱۲ تا موقعیت ۲۸ امتداد دارد و مرز راست انحصاری آن ۲۸ است:

```
        12                 20                   28                   
        |------------------|-------------------|
      Limit Left    8     Center     8     Limit Right

```

چون این بخش پالیندروم است، هر موقعیت در سمت چپ مرکز، یک موقعیت قرینه در سمت راست دارد.

برای مثال:

* موقعیت ۱۹ قرینهٔ موقعیت ۲۱ است.
* موقعیت ۱۸ قرینهٔ موقعیت ۲۲ است.
* موقعیت ۱۷ قرینهٔ موقعیت ۲۳ است.
* موقعیت ۱۶ قرینهٔ موقعیت ۲۴ است.

این تقارن به ما اجازه می‌دهد از اطلاعاتی که قبلاً دربارهٔ یک موقعیت محاسبه کرده‌ایم، برای موقعیت قرینهٔ آن استفاده کنیم.

### یک مثال ملموس

فرض کنید مرکز پالیندروم بزرگ در موقعیت ۲۰ باشد و مرز راست انحصاری آن ۲۸ باشد.

اکنون به موقعیت ۲۳ رسیده‌ایم.

مرکز قرینهٔ موقعیت ۲۳ نسبت به مرکز ۲۰ از رابطهٔ زیر به دست می‌آید:

```cpp
mirror = 2 * center - i

```

فرمول بالا از این ایده به دست آمده است: فاصلهٔ بین `i` تا مرکز را محاسبه کرده و از مرکز به سمت معکوس (چپ) به اندازهٔ همان فاصله عقب می‌رویم تا به نقطهٔ قرینه برسیم:

```
center - (i - center) = center - i + center = 2 * center - i

```

پس:

```cpp
mirror = 2 * 20 - 23 = 17

```

فرض کنید قبلاً شعاع پالیندروم موقعیت ۱۷ را برابر ۶ محاسبه کرده باشیم. (چون شعاع پالیندروم کاراکترهای ابتدایی‌تر را زودتر حساب کرده‌ایم)

آیا می‌توانیم بلافاصله نتیجه بگیریم شعاع پالیندروم موقعیت ۲۳ نیز برابر ۶ است؟

نه، لزوماً!

پالیندروم شناخته‌شده فقط تا موقعیت ۲۸ امتداد دارد. فاصلهٔ موقعیت ۲۳ تا مرز راست انحصاری برابر است با:

```
right - i = 28 - 23 = 5

```

بنابراین، اطلاعات آینه‌ای به‌تنهایی فقط می‌تواند شعاعی حداکثر برابر ۵ را تضمین کند.

اگر شعاع موقعیت آینه ۶ باشد، نمی‌توانیم بدون مقایسهٔ بیشتر شعاع ۶ را برای موقعیت فعلی تضمین کنیم.

با قرار دادن مرز انحصاری، فرمول مقداردهی اولیهٔ شعاع چنین است:

```cpp
p[i] = std::min(right - i, p[mirror]);

```

البته توجه داشته باشید که با احتساب دقیق مرز انحصاری راست در کد نهایی، فرمول به صورت `right - i - 1` اعمال می‌شود تا از محدوده خارج نشویم.

### چرا گاهی باید مقایسه‌های بیشتری انجام دهیم؟

همان‌طور که دیدیم، با استفاده از خاصیت آینه‌ای، شعاع اولیهٔ خانهٔ ۲۳ را با کمک خانهٔ ۱۷ برابر با ۵ تعیین کردیم (چون فاصلهٔ خانهٔ ۲۳ تا مرز انحصاری \(28\)، برابر با \(28 - 23 = 5\) بود).

این یعنی الگوریتم با یک پرش هوشمندانه، بدون اینکه کاراکترهای درون این بازه را یکی‌یکی مقایسه کند، بلافاصله تضمین می‌کند که پالیندروم دور خانهٔ ۲۳ حداقل طول ۵ را دارد و مستقیماً از خانهٔ ۲۸ به بعد را بررسی می‌کند. این همان نقطه‌ای است که باعث بهینه‌سازی و سرعت بالای الگوریتم می‌شود.

اما چرا پس از این جهش، باز هم به مقایسه‌های رودررو (while loop) نیاز داریم؟

دلیلش این است که محدودهٔ پالیندروم بزرگِ مرکز ۲۰ در انتهای خود (خانهٔ ۲۸) به پایان می‌رسد. ما از وضعیت کاراکترهای خارج از این مرز (یعنی سمت راست خانهٔ ۲۸ به بعد) هیچ اطلاعی نداریم. بنابراین، پس از اینکه شعاع اولیه روی عدد ۵ ست شد، باید حلقهٔ مقایسه را از سر بگیریم و کاراکترها را یکی‌یکی به جلو ببریم تا زمانی که:

    یا به انتهای رشته برسیم،

    یا به اولین جفت کاراکتر نامساوی برخورد کنیم.

اگر در جریان این مقایسه‌های جدید، پالیندرومِ مرکز ۲۳ توانست از مرز ۲۸ عبور کند و پیشتر برود، آنگاه مرکز (center) و مرز راست انحصاری (right) را به‌روزرسانی می‌کنیم تا پالیندروم‌های بعدی بتوانند از این مرز جدید نهایت استفاده را ببرند.

    خلاصه: خاصیت آینه‌ای به ما «سرعتِ جهش» می‌دهد تا از کارهای تکراری خلاص شویم، اما برای کشف مرزهای جدیدِ ناشناخته، ناگزیریم مقایسه‌های نظیربه‌نظیر را ادامه دهیم.

## ۷. دو متغیر مهم در الگوریتم Manacher

برای استفاده از خاصیت آینه‌ای، دو متغیر نگه می‌داریم:

* `center`: مرکز پالیندرومی که تاکنون دورترین مرز راست را داشته است.
* `right`: اولین موقعیت خارج از آن پالیندروم؛ یعنی مرز راست انحصاری.

اگر موقعیت فعلی `i` کوچک‌تر از `right` باشد، هنوز داخل پالیندروم راست‌گستر شناخته‌شده قرار داریم و می‌توانیم از خاصیت آینه‌ای استفاده کنیم.

اگر `i` برابر یا بزرگ‌تر از `right` باشد، شعاع اولیه را صفر در نظر می‌گیریم.

### چه زمانی مرکز و مرز راست را به‌روزرسانی می‌کنیم؟

پس از محاسبهٔ شعاع مرکز فعلی، مرز راست انحصاری جدید را به دست می‌آوریم:

\[newRight = i + p[i] + 1\]

اگر این مقدار از `right` فعلی بزرگ‌تر باشد، یعنی پالیندروم تازه به سمت راست بیشتر گسترش پیدا کرده است.

در این حالت، مرکز و مرز راست را به‌روزرسانی می‌کنیم:

```cpp
center = i;
right = i + p[i] + 1;

```

به این ترتیب، الگوریتم همیشه از پالیندرومی استفاده می‌کند که دورترین مرز راست شناخته‌شده را دارد.

نکتهٔ مهم: چون در این مقاله `right` مرز انحصاری است، باید همین قرارداد را در تمام فرمول‌ها و شرط‌ها رعایت کنیم. اگر مرز انحصاری را با آخرین موقعیت داخل پالیندروم اشتباه بگیریم، خطاهای یک‌واحدی ایجاد می‌شوند.

## ۸. الگوریتم کامل Manacher

اکنون تمام اجزای موردنیاز را در اختیار داریم:

1. تبدیل رشته برای یکسان‌سازی پالیندروم‌های زوج و فرد.
2. ایجاد آرایهٔ `p` برای نگهداری شعاع پالیندروم هر موقعیت.
3. نگهداری مرکز و مرز راست انحصاری پالیندروم شناخته‌شده.
4. استفاده از مرکز قرینه برای تعیین شعاع اولیه.
5. ادامهٔ مقایسه‌ها فقط در صورت نیاز.
6. نگهداری بهترین مرکز و بیشترین شعاعی که تاکنون پیدا کرده‌ایم.

در پیاده‌سازی زیر، تابع خود زیررشتهٔ پالیندروم را برمی‌گرداند.

### کد کامل در C++

```cpp
#include <algorithm>
#include <string>
#include <vector>

std::string longestPalindrome(const std::string& str)
{
    // Transform the string by inserting separators.
    // -1 cannot collide with any unsigned char value.
    std::vector<int> s;
    s.reserve(str.size() * 2 + 1);

    for (unsigned char c : str)
    {
        s.push_back(-1);
        s.push_back(static_cast<int>(c));
    }

    s.push_back(-1);

    const int n = static_cast<int>(s.size());

    // p[i] stores the palindrome radius around i.
    std::vector<int> p(n, 0);

    // The right boundary is exclusive.
    int center = 0;
    int right = 0;

    // Best palindrome found so far.
    int bestCenter = 0;
    int bestRadius = 0;

    for (int i = 0; i < n; ++i)
    {
        // Initialize the radius using the mirrored position.
        if (i < right)
        {
            const int mirror = 2 * center - i;

            p[i] = std::min(
                right - i - 1,
                p[mirror]
            );
        }

        // Expand while the values on both sides match.
        while (i - p[i] - 1 >= 0 &&
               i + p[i] + 1 < n &&
               s[i - p[i] - 1] == s[i + p[i] + 1])
        {
            ++p[i];
        }

        // Update the rightmost known palindrome.
        const int newRight = i + p[i] + 1;

        if (newRight > right)
        {
            center = i;
            right = newRight;
        }

        // Keep the first maximum-length answer.
        if (p[i] > bestRadius)
        {
            bestRadius = p[i];
            bestCenter = i;
        }
    }

    // Convert transformed-string indices to original indices.
    const std::size_t start =
        static_cast<std::size_t>(
            (bestCenter - bestRadius) / 2
        );

    return str.substr(
        start,
        static_cast<std::size_t>(bestRadius)
    );
}

```

### مثال استفاده

```cpp
#include <iostream>
#include <string>

std::string longestPalindrome(const std::string& str);

int main()
{
    std::cout << longestPalindrome("babad") << '\n';
    std::cout << longestPalindrome("abba") << '\n';
    std::cout << longestPalindrome("cbbd") << '\n';
    std::cout << longestPalindrome("") << '\n';
}

```

خروجی نمونه:

```
bab
abba
bb

```

برای ورودی `babad`، خروجی `aba` نیز درست است؛ زیرا هر دو زیررشته پالیندروم هستند و طول یکسانی دارند.

برای ورودی `abba`، خروجی `abba` خواهد بود.

برای ورودی `cbbd`، خروجی `bb` خواهد بود.

برای ورودی خالی، خروجی نیز رشتهٔ خالی است.

## ۹. چرا فرمول استخراج زیررشته درست است؟

پس از پایان الگوریتم، `bestCenter` مرکز بلندترین پالیندروم در رشتهٔ تبدیل‌شده و `bestRadius` شعاع آن است.

در رشتهٔ تبدیل‌شده، جداکننده‌ها و کاراکترهای اصلی به‌صورت یکی‌درمیان قرار گرفته‌اند.

در این ساختار:

* طول پالیندروم متناظر در رشتهٔ اصلی برابر `bestRadius` است.
* موقعیت شروع زیررشته در رشتهٔ اصلی از رابطهٔ زیر به دست می‌آید:

```
start = (bestCenter - bestRadius)/2
```

بنابراین، دستور زیر زیررشتهٔ موردنظر را استخراج می‌کند:

```cpp
return str.substr(start, bestRadius);

```

### آیا مرکز بلندترین پالیندروم (bestCenter) همیشه روی کاراکتر اصلی قرار می‌گیرد؟

یک نکتهٔ بسیار جالب در الگوریتم Manacher این است که اگر طول بلندترین پالیندروم در رشتهٔ اصلی بزرگ‌تر از ۱ باشد، مرکز آن در رشتهٔ تبدیل‌شده همیشه روی یک کاراکتر اصلی (و نه روی جداکننده) قرار خواهد گرفت. دلیل این پدیده به ساختار هم‌افزایی متقارن کاراکترها برمی‌گردد:

    مرکز روی کاراکتر اصلی: وقتی مرکز یک پالیندروم روی یک کاراکتر اصلی قرار می‌گیرد، کاراکترهای جداسازِ اطراف آن دقیقاً به شکل زوج‌های قرینه و همسان در دو طرفِ مرکز ظاهر می‌شوند و با کاراکترهای اصلیِ متناظر در سمت دیگر «هم‌افزایی» می‌کنند؛ در نتیجه، شعاع پالیندروم به صورت متقارن و با حداکثر سرعت رشد می‌کند.

    محدودیت جداکننده به‌عنوان مرکز: اگر مرکز روی یک جداکننده (مثل -1) قرار بگیرد، تقارنِ پیرامونیِ ساختار به‌گونه‌ای خواهد بود که طول کل آن پالیندروم همیشه یک عدد زوج در رشتهٔ تبدیل‌شده تولید می‌کند که لزوماً از نظر طولِ کاراکترهای اصلیِ واقعی، مزیتی نسبت به مرکزهای اصلی ندارد و معمولاً پالیندروم‌های بزرگ‌تر و ریشه‌دارتر، مرکز خود را روی کاراکترهای اصلی بنا می‌کنند.

بنابراین، اگرچه الگوریتم تمام موقعیت‌ها (چه کاراکترها و چه جداکننده‌ها) را به عنوان مراکز احتمالی بررسی می‌کند، اما بلندترین پالیندروم نهایی تقریباً همیشه مرکزی بر روی کاراکترهای اصلیِ معتبر خواهد داشت.

این فرمول با قرارداد تبدیل استفاده‌شده در کد سازگار است: جداکننده‌ها در اندیس‌های زوج و کاراکترهای اصلی در اندیس‌های فرد قرار دارند.

## ۱۰. نکات پیاده‌سازی و محدودیت‌ها

### رشتهٔ خالی

اگر ورودی خالی باشد، الگوریتم آرایهٔ تبدیل‌شده‌ای با یک جداکننده می‌سازد. شعاع بهترین پالیندروم صفر باقی می‌ماند و خروجی نیز رشتهٔ خالی خواهد بود.

### کاراکترهای تکراری

الگوریتم برای رشته‌هایی مانند `aaaaaa` نیز درست عمل می‌کند و کل رشته را به‌عنوان بلندترین پالیندروم برمی‌گرداند.

### رشته‌های دارای چند پاسخ

ممکن است چند زیررشتهٔ پالیندروم با طول یکسان و بیشینه وجود داشته باشند.

در کد بالا، بهترین پاسخ فقط زمانی به‌روزرسانی می‌شود که شعاع جدید بزرگ‌تر از شعاع قبلی باشد:

```cpp
if (p[i] > bestRadius)

```

بنابراین، در صورت وجود چند پاسخ هم‌طول، اولین پاسخی که الگوریتم پیدا کرده است حفظ می‌شود.

### UTF-8 و متن فارسی

`std::string` در C++ رشته را به‌صورت دنباله‌ای از بایت‌ها نگه می‌دارد. بنابراین، کد بالا برای ASCII و داده‌هایی که هر کاراکتر موردنظرشان یک بایت است مناسب است؛ اما متن فارسی معمولاً در UTF-8 با چند بایت برای هر نویسه ذخیره می‌شود.

اگر هدف، مقایسهٔ نویسه‌های فارسی باشد، باید ورودی ابتدا به دنباله‌ای از واحدهای نویسه‌ای مناسب تبدیل شود و سپس الگوریتم روی آن دنباله اجرا شود.

همچنین در متن‌های واقعی ممکن است لازم باشد پیش از پردازش، نرمال‌سازی Unicode انجام شود؛ زیرا دو شکل ظاهراً یکسان ممکن است نمایش بایتی متفاوتی داشته باشند.

### نوع داده و اندازهٔ ورودی

در این پیاده‌سازی، اندیس‌ها و شعاع‌ها از نوع `int` هستند. برای ورودی‌هایی که اندازهٔ آن‌ها ممکن است از محدودهٔ `int` فراتر برود، باید از نوع اندیس مناسب‌تری استفاده شود.

همچنین در پیاده‌سازی‌های عمومی، پیش از محاسبهٔ `2 * str.size() + 1` باید امکان سرریز اندازه بررسی شود.

## ۱۱. پیچیدگی زمانی و فضایی الگوریتم

اگر طول رشتهٔ اصلی \(n\) باشد، طول رشتهٔ تبدیل‌شده برابر است با:

\[2n + 1\]

این مقدار همچنان از مرتبهٔ \(O(n)\) است.

### پیچیدگی زمانی

در روش ساده، هر مرکز ممکن است بخش‌هایی را که قبلاً بررسی شده‌اند دوباره پیمایش کند؛ بنابراین پیچیدگی زمانی در بدترین حالت \(O(n^2)\) است.

اما در Manacher، شعاع پالیندروم‌های قبلی و خاصیت آینه‌ای برای جلوگیری از تکرار بسیاری از مقایسه‌ها استفاده می‌شوند.

هر بار که گسترش از مرز راست شناخته‌شده عبور می‌کند، مرز راست جلوتر می‌رود. در نتیجه، مجموع گسترش‌های موفق در کل الگوریتم خطی باقی می‌ماند.

پس پیچیدگی زمانی الگوریتم برابر است با:

\[\boxed{O(n)}\]

### پیچیدگی فضایی

برای نگهداری رشتهٔ تبدیل‌شده و آرایهٔ شعاع‌ها به حافظهٔ اضافی نیاز داریم.

هر دو آرایه متناسب با طول رشته هستند؛ بنابراین پیچیدگی فضایی برابر است با:

\[\boxed{O(n)}\]

## جمع‌بندی

در این مسئله، ابتدا مفهوم پالیندروم و روش سادهٔ بررسی آن را آموختیم. سپس دیدیم که پالیندروم‌ها می‌توانند طول زوج یا فرد داشته باشند و بررسی جداگانهٔ این دو حالت، طراحی الگوریتم را دشوارتر می‌کند.

با قرار دادن جداکننده میان کاراکترها، هر دو نوع پالیندروم را به یک ساختار مشترک تبدیل کردیم. سپس روش سادهٔ گسترش از مرکز را پیاده‌سازی کردیم و متوجه شدیم که این روش ممکن است مقایسه‌های تکراری زیادی انجام دهد.

ایدهٔ اصلی Manacher استفاده از خاصیت آینه‌ای است: وقتی یک پالیندروم بزرگ را می‌شناسیم، اطلاعات مربوط به مرکزهای قرینهٔ آن می‌تواند برای محاسبهٔ شعاع مرکزهای جدید استفاده شود.

البته این اطلاعات فقط تا مرز پالیندروم شناخته‌شده قابل اعتماد است و برای گسترش بیشتر، همچنان باید مقایسه‌های واقعی انجام شوند.

در نهایت، الگوریتم Manacher می‌تواند بلندترین زیررشتهٔ پالیندروم را در زمان خطی پیدا کند.

نکتهٔ اصلی برای به خاطر سپردن: قدرت Manacher فقط در پیدا کردن پالیندروم‌ها نیست؛ قدرت آن در استفاده از اطلاعاتی است که قبلاً محاسبه کرده‌ایم تا از انجام دوبارهٔ محاسبات غیرضروری جلوگیری کنیم.
