## راهنمای جامع حل مسئله Move Zeroes (سوال مصاحبه فیس‌بوک/متا)

مسئله **Move Zeroes** یکی از پرکاربردترین سوالات سطح Easy در پلتفرم LeetCode و الگوی تکرارشونده در مصاحبه‌های شرکت‌های بزرگ تکنولوژی نظیر Meta (Facebook) است. این مسئله مفهوم پیمایش آرایه‌ها و مدیریت حافظه درجا (In-place) را ارزیابی می‌کند.

---

### ۱. صورت مسئله

یک آرایه از اعداد صحیح به نام `nums` به شما داده شده است. هدف این است که تمام مقادیر `0` را به انتهای آرایه منتقل کنید، به طوری که:

* ترتیب نسبی عناصر غیرصفر حفظ شود.
* تغییرات حتماً **درجا (In-place)** انجام شود (بدون کپی کردن آرایه یا ساخت آرایه جدید).

**مثال ورودی و خروجی:**

| ورودی | خروجی |
| --- | --- |
| `[0, 1, 0, 3, 12]` | `[1, 3, 12, 0, 0]` |
| `[0]` | `[0]` |

---

### ۲. استراتژی حل (روش دو اشاره‌گر - Two Pointers)

روش ساده اما نادرست این است که یک آرایه جدید بپذیریم و غیرصفرها را درون آن بریزیم؛ اما این کار شرط حافظه درجا را نقض می‌کند.

بهترین راهکار استفاده از الگوریتم **دو اشاره‌گر** در یک پیمایش (Single Pass) است:

1. **اشاره‌گر اول (`lastNonZeroFoundAt`):** مقصدی را پیگیری می‌کند که عنصر غیرصفر بعدی باید در آنجا قرار گیرد.
2. **اشاره‌گر دوم (`i`):** کل آرایه را از ابتدا تا انتها پیمایش می‌کند.

در هر مرحله، اگر عنصر فعلی (`nums[i]`) مخالف صفر بود، جای آن را با خانه `lastNonZeroFoundAt` تعویض (Swap) کرده و سپس `lastNonZeroFoundAt` را یک واحد به جلو می‌بریم. با این الگوریتم، تمام صفرها بدون نیاز به حلقه دوم به انتهای آرایه رانده می‌شوند.

---

### ۳. پیاده‌سازی به زبان ++C

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        // اشاره‌گر برای ثبت موقعیت قرارگیری عنصر غیرصفر بعدی
        int lastNonZeroFoundAt = 0;
        
        // پیمایش یک‌باره آرایه
        for (int i = 0; i < nums.size(); i++) {
            if (nums[i] != 0) {
                // جابه‌جایی عنصر غیرصفر به اولین موقعیت خالی در سمت چپ
                swap(nums[lastNonZeroFoundAt], nums[i]);
                lastNonZeroFoundAt++;
            }
        }
    }
};

```

توضیح اضافه برای کسانی که هنوز روش حل مساله را درک نکرده اند:

برای درک شهودی الگوریتم «انتقال صفرها» (Move Zeroes) بدون درگیر شدن با جزئیات فنی کدنویسی، می‌توان رفتار دو اشاره‌گر را در قالب یک **مدل مفهومی استاندارد** تشریح کرد.

**مدل مفهومی الگوریتم**

در این الگوریتم، آرایه به عنوان منطقه‌ای از خانه‌های متوالی در نظر گرفته می‌شود که دو عنصر عملیاتی با وظایف مجزا در آن حرکت می‌کنند:

* **پیمایش‌گر (اشاره‌گر اول):** وظیفه کاوش تک‌تک خانه‌های آرایه از ابتدا تا انتها را بر عهده دارد.
* **ثبت‌کننده (اشاره‌گر دوم):** موقعیتِ نخستین خانهٔ حاوی صفر (جایگاه آماده برای دریافت عدد غیرصفر) را پیگیری می‌کند.

---

**قوانین اجرایی الگوریتم**

پیمایش‌گر خانه به خانه جلو می‌رود و در هر گام بر اساس ارزش خانه‌ای که در آن قرار دارد، یکی از دو حالت زیر را اجرا می‌کند:

* **مواجهه با عدد صفر:** پیمایش‌گر بدون هیچ اقدامی یک گام به جلو حرکت می‌کند؛ اما ثبت‌کننده در موقعیت خود باقی می‌ماند تا جایگاه صفرِ شناسایی‌شده حفظ شود.
* **مواجهه با عدد غیرصفر:** مقدار خانه فعلی با خانه‌ای که ثبت‌کننده روی آن ایستاده تعویض (Swap) می‌شود. در این حالت، هر دو اشاره‌گر یک گام به جلو پیش می‌روند.

---

**تحلیل گام‌به‌گام عملکرد**

جدول زیر روند تغییرات را روی آرایه نمونه `[0, 1, 0, 3]` نشان می‌دهد:

| گام | خانه مورد بررسی | وضعیت عملیات | آرایه حاصل | موقعیت ثبت‌کننده |
| --- | --- | --- | --- | --- |
| **آغاز** | اندیس 0 (مقدار `0`) | صفر شناسایی شد؛ عدم تغییر و عبور پیمایش‌گر | `[0, 1, 0, 3]` | اندیس 0 |
| **۱** | اندیس 1 (مقدار `1`) | عدد غیرصفر؛ تعویض با خانه ثبت‌کننده (اندیس 0) | `[1, 0, 0, 3]` | اندیس 1 |
| **۲** | اندیس 2 (مقدار `0`) | صفر شناسایی شد؛ عدم تغییر و عبور پیمایش‌گر | `[1, 0, 0, 3]` | اندیس 1 |
| **۳** | اندیس 3 (مقدار `3`) | عدد غیرصفر؛ تعویض با خانه ثبت‌کننده (اندیس 1) | `[1, 3, 0, 0]` | اندیس 2 |

در این ساختار، ثبت‌کننده همواره روی نخستین صفرِ بلاتکلیف کمین می‌کند. به محض آنکه پیمایش‌گر یک عدد غیرصفر در ادامه آرایه کشف کند، با تعویض جایگاه این دو عنصر، عدد غیرصفر به بخش چپ آرایه منتقل شده و صفرها به‌طور خودکار به سمت انتها رانده می‌شوند.
---

### تشبیه «کاوشگر» و «جمع‌آوری‌کننده»

فرض کن یک صف از جعبه‌ها داری. بعضی از جعبه‌ها داخلشون **هدیه** است (اعداد غیرصفر) و بعضی‌ها **خالی** هستند (صفرها). هدف ما اینه که همه هدیه‌ها رو بیاوریم اول صف و جعبه‌های خالی برن آخر.

برای این کار دو نفر رو استخدام می‌کنیم:

* **کاوشگر (اشاره‌گر اول):** از اول تا آخر صف قدم می‌زنه و داخل جعبه‌ها رو نگاه می‌کنه.
* **جمع‌آوری‌کننده (اشاره‌گر دوم):** منتظر می‌مونه تا اولین جالی خالی برای گذاشتن هدیه رو تحویل بگیره.

---

### قوانین ساده بازی

1. **اگر کاوشگر جعبه خالی (صفر) دید:**
هیچ کاری نمی‌کنه! خودش یک قدم می‌ره جلو، اما **جمع‌آوری‌کننده سر جاش می‌مونه** (در واقع جمع‌آوری‌کننده الان داره روی یک صفر می‌ایسته و منتظر هدیه‌ست).
2. **اگر کاوشگر هدیه (عدد غیرصفر) دید:**
هدیه را با جعبه‌ای که **جمع‌آوری‌کننده** روی اون ایستاده جابه‌جا (Swap) می‌کند. بعد از این جابه‌جایی، **جمع‌آوری‌کننده یک قدم می‌ره جلو**.

---

### اجرای قدم‌به‌قدم روی یک مثال واقعی

آرایه اولیه: `[0, 1, 0, 3]`

| گام | کار کاوشگر | وضعیت آرایه | وضعیت جمع‌آوری‌کننده |
| --- | --- | --- | --- |
| **شروع** | روی خانه اول ایستاده | `[0, 1, 0, 3]` | روی خانه اول (نمایه 0) |
| **۱** | صفر دید! رد میشه. | `[0, 1, 0, 3]` | سر جاش روی خانه اول می‌مونه. |
| **۲** | عدد `1` دید! جای `1` را با خانه جمع‌آوری‌کننده جابه‌جا می‌کنه. | `[1, 0, 0, 3]` | یک قدم می‌ره جلو (روی خانه دوم). |
| **۳** | صفر دید! رد میشه. | `[1, 0, 0, 3]` | سر جاش روی خانه دوم می‌مونه. |
| **۴** | عدد `3` دید! جای `3` را با خانه جمع‌آوری‌کننده جابه‌جا می‌کنه. | `[1, 3, 0, 0]` | یک قدم می‌ره جلو. |

**نتیجه کلام:** اشاره‌گر دوم (جمع‌آوری‌کننده) همیشه روی **اولین صفرِ بلاتکلیف** کمین کرده تا به محض اینکه اشاره‌گر اول یک عدد غیرصفر پیدا کرد، جای اون‌ها رو با هم عوض کنه!

---

### ۴. تحلیل پیچیدگی (Complexity Analysis)

* **پیچیدگی زمانی (Time Complexity):** برابر با $O(n)$ است؛ زیرا آرایه تنها یک بار پیمایش می‌شود ($n$ تعداد عناصر آرایه است).
* **پیچیدگی فضایی (Space Complexity):** برابر با $O(1)$ است؛ زیرا هیچ حافظه اضافی اختصاص داده نشده و جابه‌جایی‌ها تماماً درجا انجام می‌شوند.
