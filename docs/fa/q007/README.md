# سوال 007:  مساله یافتن تعداد اعداد اول کوچکتر از یک عدد تعیین شده آمازون

صورت مسئله: هدف مسئله این است که تعداد اعداد اول بین 1 تا عدد ورودی N را پیدا کنیم، بدون اینکه خود عدد N را بررسی کنیم که اول هست یا نه. یعنی بازه ما از 1 تا N-1 خواهد بود. البته می توان خود عدد N را هم شامل کرد یا نکرد!
------
## روش ساده (Brute Force)
اولین روشی که به ذهن می‌رسد این است که از عدد 2 تا N-1 یک حلقه بزنیم (با متغیر i). برای هر عدد i بررسی کنیم که آیا بر عددی بین 2 تا i/2  بخش‌پذیر است یا نه.
اگر بخش‌پذیر باشد، یعنی اول نیست. اگر تا i/2 هیچ مقسوم‌علیه‌ای پیدا نشود، آن عدد اول است.
------
چرا تا i/2 کافی است؟
چون کوچک‌ترین مقسوم‌علیه بعد از 1 عدد 2 است. اگر عدد N بر 2 بخش‌پذیر باشد:
```text
N = 2 × X          -->       X = N / 2
```
اگر بر 3 بخش‌پذیر باشد:
```
N = 3 × Y                  -->        Y = N / 3
```
واضح است که هرچه مقسوم‌علیه بزرگ‌تر شود، عدد مقابل آن کوچک‌تر می‌شود.
بزرگ‌ترین مقسوم‌علیه ممکن زمانی رخ می‌دهد که کوچک‌ترین ضریب مقابل آن یعنی 2 باشد.
بنابراین هیچ مقسوم‌علیه‌ای نمی‌تواند بزرگ‌تر از N/2 باشد.
------
## پیاده‌سازی منطقی روش ساده
برای هر عدد i:
یک متغیر بولین به نام is_prime  تعریف می‌کنیم.
اگر در حلقه داخلی j به عددی رسیدیم که i % j == 0 بود:
is_prime  را false می‌کنیم
از بررسی آن i خارج می‌شویم (skip)
اگر تا پایان حلقه داخلی باقی‌مانده صفر پیدا نشد:
i  یک عدد اول است
شمارنده اعداد اول (prime_counter) را یک واحد افزایش می‌دهیم!

## روش بهینه – الگوریتم غربال
این روش همان الگوریتم معروف Eratosthenes است که به نام "Sieve of Eratosthenes" شناخته می‌شود.

## ایده اصلی
به جای اینکه دنبال اعداد اول بگردیم، اعداد غیر اول را حذف می‌کنیم.
یک جدول از 0 تا N می‌نویسیم.
عدد 0 و 1 را حذف می‌کنیم چون اول نیستند.
از عدد 2 شروع می‌کنیم:
چون هنوز حذف نشده، آن را اول در نظر می‌گیریم.
سپس مضارب آن را حذف می‌کنیم:
2×2 ، 3× 2 ، 4× 2 ، ...

## چرا از 3×3 شروع می‌کنیم؟
وقتی به عدد 3 می‌رسیم:
 3×2 قبلاً حذف شده است چون برابر 3×2 است و در مرحله قبل حذف شده بود.
پس برای جلوگیری از تکرار، حذف مضارب هر عدد را از i×i شروع می‌کنیم.
چون:  i×(i−1) قبلاً در مرحله (i−1) حذف شده است.

## قانون کلی الگوریتم
اگر عددی قبلاً حذف شده باشد، دیگر مضارب آن را بررسی نمی‌کنیم.
حذف مضارب هر عدد از i×i شروع می‌شود.
این کار را تا زمانی ادامه می‌دهیم که i×i < N باشد.
چون اگر i×i از N بزرگ‌تر شود، دیگر مضرب جدیدی داخل محدوده نداریم.

## پیاده‌سازی برنامه‌نویسی
### تعریف آرایه
یک آرایه بولین با اندازه N تعریف می‌کنیم.
اندیس‌ها از 0 تا N-1 هستند.
همه را ابتدا true قرار می‌دهیم (فرض می‌کنیم همه اول هستند).
خانه 0 و 1 را false می‌کنیم.
اگر بخواهیم خود N هم بررسی شود، آرایه را با اندازه N+1 تعریف می‌کنیم.
سپس به جای تمرکز روی اینکه N هم جزو شمارش است یا خیر، روی سایز آرایه تمرکز می کنیم!

## جلوگیری از محاسبات تکراری
در جدول ضرب می‌بینیم:

```text
2×3 = 6
3×2 = 6
```
پس نباید هر دو را محاسبه کنیم.
برای جلوگیری از تکرار:
برای هر عدد   i
حذف را از i×i شروع می‌کنیم
و این کار را تا زمانی ادامه می‌دهیم که i×i < N باشد.

## نکته مهم منطقی
اگر عددی X به صورت A×B ساخته شده باشد:
```
A × B = X
```
و اگر قبلاً مضارب A را حذف کرده باشیم،
در آن صورت خود X و تمام مضارب آن نیز قبلاً حذف شده‌اند.
پس اگر خانه‌ای false باشد،
دیگر نه خود آن و نه مضاربش را بررسی نمی‌کنیم.
چون قبلاً در مراحل قبل حذف شده‌اند.

## جمع‌بندی نهایی
روش ساده دارای پیچیدگی زمانی تقریباً O(N²) است.
اما روش غربال دارای پیچیدگی زمانی حدود O(N log log N) است.
به همین دلیل برای مقادیر بزرگ N، الگوریتم غربال بسیار سریع‌تر و بهینه‌تر است.

## الگریتم نهایی
```cpp
int countPrimes(int n) {
    if (n <= 2) return 0;

    vector<bool> isPrime(n, true); 
          //vector with n items which all are true
    isPrime[0] = isPrime[1] = false; // 0  and 1 are not prime at all

    for (int i = 2; i * i < n; i++) {
        if (isPrime[i]) {
            for (int j = i * i; j < n; j += i) {
                isPrime[j] = false;
            }
        }
    }

    return count(isPrime.begin(), isPrime.end(), true);
}
```

 مطالعه آزاد:
روش بهینه شمارش تعداد اعداد اول بین 1 تا N:
دیدمان را معکوس می کنیم و این بار تمام اعداد غیر اول را پیدا می کنیم و از بازی حذفشان می کنیم تا تعداد اعداد اول به دست آید!
ایده ساده آنست که شما اعداد بین 0 تا عدد N را در یک جدول بنویسید و از ابتدا عدد 0 و 1 را خط بزنید چون اعداد اول نیستند! سپس از عدد 2 شروع کنیم و خود عدد 2 را به خاطر خط نخوردنش تا به الان به عنوان عدد اول در نظر بگیریم و سپس  تمام مضارب آن یعنی 2 * 2  و سپس 3 * 2 و سپس  4 * 2 را خط بزنیم و تا آخرین عدد جدول پیش بروید. سپس از عدد بعدی یعنی عدد 3 که هنوز خط نخورده شروع کنید و اعداد   2 * 3 و سپس 3 * 3 و 4 * 3 و .. را تا آخر خط بزنید!
در اینجا به یک نکته می رسیم! 2 * 3 قبلا خط زده شده است! چرا؟ چون 2 * 3   همان  3 * 2 است که جزو یکی از مضارب 2 بود که قبلا خط خورده است! پس در مورد عدد 3 از 3 * 3 شروع می کنیم. پس قانون کلی تا به حال اینکه در هر مرحله از خط زدن اعداد جدول، مضارب بزرگتر یا مساوی هر عدد خط نخورده به بعد را حذف می کنیم چون اعداد مضارب کوچکتر قبلا خط خورده است!
در مرحله بعد وقتی ببینیم عدد 4 قبلا خط خورده است، دیگر می دانیم مضارب عدد 4 هم خط خورده است!
قانون کلی تا به اینجا، اینکه اگر در مراحل بعدی به عدد خط خورده رسیدیم، دیگر مضارب آنرا هم رها می کنیم چون قبلا مضارب آن هم خط خورده شده است!
سپس می بینیم عدد 5 خط نخورده است! پس خود آنرا به عنوان عدد اول رها می کنیم در مرحله بعد از 5 * 5 شروع می کنیم! چرا از               
2 * 5 شروع نکردیم؟ چون عدد 2 * 5 مساوی همان  5 * 2 است که قبلا حذف شده است! چرا از 3 * 5 شروع نکردیم؟

ارائه روش برنامه نویسی ایده بالا:
ابتدا آرایه ای بولین به طول عدد n می سازیم و تمام خانه های آنرا true به نشانه IsPrime می کنیم. خانه 0 آن برای عدد 0 و خانه 1 آن برای عدد 1 و بقیه خانه ها تا N-1 پیش می رود. چون نیاز نداریم اول بودن و نبودن خود N را بشماریم، پس اعداد 0 تا N-1 در این الگریتم (خانه های 0 تا N-1 آرایه) بررسی می شوند! خانه های 0 و 1 آنرا false می کنیم چون نه عدد 0 و نه 1 جزو اعداد اول نیستند!
نکته: می توان شامل بودن یا نبودن خود عدد N در محاسبات را با تعریف آرایه مربوطه با N خانه برای حالت شامل نبودن N و تعریف آرایه با N+1 خانه برای حالت شامل بودن خود عدد N در محاسبات انجام داد! سپس دیگر محاسبات را به جای عدد N حول Length آرایه بررسی می کنیم!
حال مقادیر داخل خانه 2 تا آخرین خانه آرایه معین کننده اول بودن و نبودن هر خانه است. 
در نتیجه مانند جدول ضرب اعداد که:
2 * 1 = 2   ,   2 * 2 = 4   ,  ….   ,  3 * 1 = 3   ,    3 * 2 = 6 , … 9 * 9 = 81  ,  …
پس از اعداد 2 تا N-1 هر عدد را ابتدا ضربدر 2 و سپس ضربدر 3  و ضربدر ... تا ضرب در X می کنیم و خانه هایی از آرایه را که مقدار اندیسشان برابر حاصل ضرب ها است را false می کنیم چون خانه هایی که اندیس آنها برابر حاصل ضرب مد نظر هستند یعنی حاصل دو ضرب غیر از اعداد 1 و N هستند و با این حال اعداد اول نیستند! اما این رویه هنوز با بهترین رویه فاصله دارد!
2 * 2 = 4  ,    2 * 3 = 6   ,  2 * 4 = 8,    2 * 5 = 10
3 * 2 = 6 ,   3 * 3 = 9  ,  3 * 4 = 12,     3 * 5 = 15 
4 * 2 = 8 ,  4 * 3 = 12,   4 * 4 = 16,    4 * 5 = 20
در شکل بالا محاسباتی که نتیجه ضربشان برابر با هم هستند را با رنگ های مشابه قرمز و قهوه ای و نارنجی نشان داده ایم و ما باید در ادامه کار، از تکرار این محاسبات حذر کنیم! نتیجه می گیریم که در هر سطر بالا، برای عدم تکرار دوباره محاسبات قبلی، محاسبات هر عدد باید از i  *  i شروع شود چون i * (i-1) قبلا در نوبت i-1  محاسبه شده اند! اما این محاسبه تا i ای پیش می رود که i * i اش کوچکتر  از N شود! چون حد کرانه بالای مجاز ضربها خود عدد N است!
فکت های مهم برای هدایت ادامه کار: اگر   فرض کنیم در ضرب دو عدد A * B که مساوی X شود، حداقل یکی از دو عدد A یا B یا هر دو عدد اول باشند، در روش خط زدن مضارب اعداد به روش بالا برای یافتن اعداد اول، خود X و همچنین تمام مضارب X هم قبل از رسیدن به X حذف شده اند! چرا؟
A * B = X       2 * A* B = 2 * X   A * (2 * B) = 2 * X   
A * B = X       3 * A* B = 3 * X   A * (3 * B) = 3 * X
…
…   
A * B = X       α * A* B = α * X   A * (α * B) = α* X   

همچنان که می دانید، قبلا تمام مضارب A را تا رسیدن به عدد N از آرایه حذف کرده ایم (false کرده ایم!) پس با این اوضاف هم X و هم مضارب X را هم حذف کرده ایم!  پس شروطمان را به روز می کنیم. در بررسی خانه های آرایه، اگر خانه ای قبلا false شده باشد، نه آن و نه مضاربش را بررسی نمی کنیم چون در اعداد قبلی هم آن و هم مضاربش بررسی و false شده اند!
روش نهایی: کد زیر روش نهایی حل این مساله است!  اگر عدد مد نظر کمتر از1 بود که مقدار 0 یعنی هیچ عدد اول ریترن نمی شود چون نه 0 و نه 1 اعداد اول نیستند! (در مورد اعداد منفی که محاسبه اعداد اول پشتیبانی نمی شود!)
سپس آرایه داینامیک بولین با مقادیر پیش فرض true به معنی اول بودن به تعداد خانه های عدد ورودی ساخته می شود!
ایندکس 0 و 1 این آرایه را false می کنیم چون عدد 0 و 1 اول نیستند! البته اگر مساله به ما بگوید که خود عدد N هم باید بررسی شود، تعداد خانه های این آرایه باید N + 1 باشد! (تمرین خوب اینکه می توانیم بعد از تخصیص فضا به آرایه بر اساس بررسی یا اغماض خود N، با Length آرایه سر و کار داشته باشیم نه با بررسی N یا N + 1 بودن!)
حال با توجه به اینکه باید از ایندکس دوم آرایه (به نماد عدد 2) بررسی ها را شروع کنیم، می دانیم در هر بررسی برای حذر از بررسی ایندکس های قبلی، باید مقدار خانه های با ایندکش مضارب i * i تا i * (i+1)  و i * (i+2) و ... را تا جایی که i  * x در حد رنج N باشد، را false کنیم.  برای صرفه جویی زمانی بررسی می کنیم که آیا i * i در داخل رنج مجاز است یا خیر؟ برای این کار به صورت ساده می گوییم باید از 2 تا جایی که i  در رنج ceil جذر N قرار بگیرد پیش می رویم! چون وقتی i به نقطه ای برسیم که i * i بالاتر از N باشد، یعنی مضارب این عدد از N بزرگتر هستند!
بر اساس قضیه مطرح شده بالا، گفتیم وقتی به هر عدد می رسیم که قبلا به عنوان مضارب اعداد اول پایینتر حذف شده اند، مضارب عدد حذف شده هم اول نیستند و قبلا حذف شده اند! پس از false کردن دوباره مضارب آن اجتناب می کنیم! For دوم سعی می کند ضریب پیدا شده در کرانه مجاز را به دست آورده و خانه مربوطه را false کند!
